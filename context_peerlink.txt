# 2. PROJECT PURPOSE

PeerLink is a closed-campus peer-to-peer platform.

The core idea is:

> A verified university student can tell PeerLink what they need, discover another student who can provide it, and request their help.

The long-term system will contain:

- Student registration and verification
- Student profiles
- Skills
- Skill/service listings
- Search
- Service requests
- Accept/reject requests
- AI assistant
- Messaging
- Ratings/reviews
- Borrow/lend
- Marketplace
- Notifications
- Moderation
- Administration

For THIS implementation, only build the most important foundation and core workflow.

# 51. UI/UX DESIGN DIRECTION — IMPORTANT

The visual design of PeerLink should take inspiration from the **Mona Sans / GitHub design language** and modern editorial/product interfaces.

Reference:

https://github.com/mona-sans

The reference is primarily a DESIGN INSPIRATION.

Do not copy the GitHub website.

Do not copy proprietary layouts.

Instead, take inspiration from:

- Typography
- Clean hierarchy
- Spacious layouts
- Strong use of whitespace
- Modern sans-serif typography
- Subtle borders
- Restrained visual decoration
- Editorial composition
- Clear information hierarchy
- Minimal visual noise
- Smooth interaction states

The goal is to make PeerLink feel like a **modern university product**, not a generic CRUD dashboard.

---

# 51.1 ELIMINATE THE "BOXY CRUD APP" LOOK

This is extremely important.

Do NOT make every piece of content a:

```text
┌─────────────────────┐
│                     │
│       CARD          │
│                     │
└─────────────────────┘
```

Avoid excessive:

- Cards
- Rounded rectangles
- Borders around everything
- Drop shadows
- Floating panels
- Bootstrap-style boxed components
- Equal-sized dashboard tiles
- Excessive containers

The application should NOT look like a collection of boxes.

Instead, use:

- Whitespace
- Typography
- Horizontal rules
- Subtle separators
- Section spacing
- Alignment
- Grid relationships
- Large headings
- Inline actions
- Underlined/hover states
- Small metadata
- Asymmetric layouts where appropriate

---

# 51.2 TYPOGRAPHY-FIRST DESIGN

Typography should be one of the primary visual elements.

Use **Mona Sans** if it can be legally and technically included appropriately in the project.

If not, use a close modern system sans-serif fallback.

Example:

```css
font-family:
  "Mona Sans",
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  sans-serif;
```

Use typography to establish hierarchy.

For example:

```text
Small label
───────────

Find the right
person on campus.

Large heading

A short supporting sentence explaining
what PeerLink can help you find.
```

Avoid making every heading look like a Bootstrap heading.

---

# 51.3 COLOR SYSTEM

Use a restrained color palette.

Do not use many bright colors.

The primary interface should be mostly:

- Neutral background
- Dark text
- Muted secondary text
- Subtle borders
- One primary accent color

Use color primarily to communicate:

- Primary actions
- Success
- Warning
- Error
- Important states

Do not turn every section into a different colored card.

---

# 51.4 BORDERS AND DIVIDERS

Prefer subtle dividers over boxes.

For example:

```text

────────────────────────────────────────────

JavaScript                     Intermediate

```

instead of:

```text
┌──────────────┐
│ Python       │
│ Advanced     │
└──────────────┘

┌──────────────┐
│ JavaScript   │
│ Intermediate │
└──────────────┘
```

Use borders intentionally.

A border should communicate structure, not decoration.

# 51.5 BUTTON DESIGN

Avoid huge rounded "pill" buttons everywhere.

Primary actions should be visually obvious but restrained.

For example:



Do not make every button a floating pill.

Use different visual weights:

```text

Secondary action
Text/link action
Destructive action
```

- Desktop
- Laptop
- Tablet
- Mobile

- Stack important content

- Keep touch targets usable
- Do not simply shrink desktop cards

- Search-result appearance

- Large animations
- Constant movement
- Decorative animations everywhere

The interface should feel calm and professional.
